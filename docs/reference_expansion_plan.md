# 引用支持率与 recall：定位问题及补充资料方案

## 结论

不能把 v17 的引用实质支持 2/6 和风险 recall 5/14 全归因于资料数量。当前已有两份 CEA 租约模板、135 个条款/附表片段，以及四份注册资料的 45 页索引。存在覆盖缺口，但本轮多项失败是找到了真实出处后，仍比较错了义务、触发条件或例外。新增资料尚未进入冻结的预测器，不宣称效果已经提高。

在本轮六条非拒答结果中，两个论点得到内部初审支持，三个不支持，一个不确定按失败计。主要问题包括：把合同未明确写出的“立即”加入解释；把退款后索赔当成扣押金流程；只比较调解部分就让包含退款期限的整段通过；把单次行使与证据要求合并成一个没有完整依据的论点。这不是随意多加几份合同能够解决的问题。标签正确与解释正确是两件事。

## recall 为什么低

十四条风险标签中只报出五条，漏掉九条。总计十四条拒答中有四条本来就是 gold insufficient_evidence，不能为了 recall 把这些也改成风险。最终拒答理由的原样分组是：

| 主要拒答理由 | 案例数 | 该如何改，而不是放松安全检查 |
|---|---:|---|
| 把一个参考段落说成穷尽全部情况 | 4 | 把论点改成当前段落支持的有限差异，补齐相关条款，再核对条件 |
| 合同没出现某词，就推断全合同删掉保护 | 3 | 只在明确转移责任或扩张义务时标风险；缺失上下文时索取相关条款 |
| 用参考摘录的沉默推断合同级规则 | 2 | 检索附表及关联条款；无支持就拒答，不声称“仅允许/绝不允许” |
| 特殊 HDB 审批与转租的关系不在模板内 | 1 | 补 HDB 官方审批规则，保留审批范围和仍需合同许可的区别 |
| 维修归责不支持另一个鉴定/争议费用机制 | 1 | 分开比较责任与争议费用，后者必须有直接依据 |
| 选了不存在/不匹配的 evidence ID | 1 | 输出前限制到本次候选 ID，给模型明确的对应关系 |
| 比较主题与参考主题不一致 | 1 | 把补足押金与违约补救、终止等流程分开路由 |
| 独立模型核验未支持全部比较 | 1 | 看逐论点失败原因，重建证据包；不能把模型核验自动当成人类正确答案 |

这张表统计的是全部最终拒答理由，不是说所有十四条都本应通过。它不替代独立法律标注，也不改变原来的 gold 或结果。

## 更重要的比较逻辑改进

1. **按义务取证而不是只按关键词取前四段。** 押金拆为扣款条件、通知/补救、确认损坏、退款期限、退款后追索及补足押金；维修拆为原因、损耗例外、金额上限、审批及鉴定费。检索 CEA 附表和关联条款组成证据包，不是把全文塞进 prompt。
2. **保留条件和来源身份。** 明确这是推荐模板差异、官方住房政策背景，还是争议途径说明。同一个引用只支持其主题；住房政策不能充当退押金法律标准。金额、期限、合同当事人、触发事件和例外分别比对。
3. **只输出证据能承受的论点。** 不生成“只要、所有、只能、一定违法、全合同没有”等无法证明的词。看出一项有依据的不利义务可以给有限风险提示，明确其他义务未评估；但只有一项等义，不能给整段 pass。
4. **给拒答可操作的原因。** 区分资料确实不覆盖、上下文缺失、证据选错和推理核验失败；界面仍只保留既有三个完成标签及 offline model_needed，不增加粉饰结果的分类指标。若缺合同上下文，指明应补哪段。
5. **离线先验收，再考虑付费。** 为“退款后追索≠扣押金”“补足押金≠违约补救”“推荐模板≠法律强制”及房型/当事人错配建立非案例 ID 特判的测试。先确认引用是否真的直接支持各论点，再冻结下一版。测试通过不是新的模型成绩。

这是尚未接入预测器的后续方案。接入新来源需要单独的索引版本和运行冻结，不能修改 v16/v17 快照。旧二十条只能回归；真正泛化需要新的独立编写与标注案例。所有风险标签、引用审核分母、错误及拒答均要保留；不靠删掉难例或只统计通过输出达到 95%。付费测试另行确定范围和预算，不因本次查资料自动启动。
