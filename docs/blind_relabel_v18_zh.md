# 新资料下的独立重新标注：v18

接入新依据后，可以改变标签。正确做法是建立新标签版本，而不是覆盖旧评测。v16/v17 的输入、标签、预测、初审和分数仍作为历史记录。

## 你怎样交给另一个模型

1. 解压本机的 `submission/Blind_Review_v18/` 材料包。
2. 开一个没有本项目历史对话的新窗口，最好使用不同供应商的模型。只上传包内文件，不发整个仓库、旧审核表、旧标签、模型预测、错误分析或成绩目标。
3. 先发 `REVIEWER_PROMPT_ZH.md`，然后发 `cases.input_only.json`、两份 CEA 模板、七份官方正文和 `source_manifest.json`。内容过长时逐份上传，要求读取齐全后才开始；未读取的资料必须声明，不能假装看过。
4. 对方输出逐条标注 JSON、完整对话和运行信息。保留模型名称/版本、日期、是否浏览、是否完整读完各文件。不要只返回汇总表。
5. 把结果交回来。我们先核对原文、适用范围和标注一致性，处理争议；你确认后冻结新版标签，再运行预测。不要向标注模型透露预测结果，也不要让它“帮助提高成绩”。

没有与旧对话交叉，是有用的防偏措施；但不同窗口不保证模型误差相互独立。应在报告里称为“外部模型辅助重新标注、项目负责人复核”，不能称为独立法律专家金标准。

## 标签规则

- `review_required`：至少一个明示、具体、潜在对租客不利且可询问澄清的差异，由相关 CEA 模板正面条款支持；或一项适用条件已明确的官方住房/税费规则与合同的明确安排不一致。记录具体机制及后果。不是“表述不同”或“与模板不完全一样”。
- `no_material_difference_found`：选定条款的所有重要义务、条件、期限、费用、例外和争议机制都有依据支持等义或租客受益，并无有据的潜在不利差异。这只是有限对照，不批准整个租约。
- `insufficient_evidence`：找不到对应依据、适用条件缺失、只有引用沉默/合同片段遗漏、重要机制仍未覆盖，且没有另一项已经充分支持的具体不利差异。

一个已支持的风险可以单独提示，但必须明确其他事项未获批准；不得用一个等义的维修付款义务，替整句中的鉴定费、举证效力或终止条件放行。

## 依据的边界

- CEA 两份租约模板是对照样本，不是强制法律；空白金额、月数和日期是变量。选择具体金额不自动构成风险。
- HDB：区分房主出租与租客再出租、整套与卧室、登记变更与新租客入住前审批、房主持续居住义务。不要把房主责任直接变成普遍的租客责任。
- URA：保留面积、人数是否属于同一家庭、登记和有效期条件。“可八人”不是无条件规则。
- IRAS：税费和付款责任。协议约定与没有约定时的默认付款人不同；税费资料不能证明普遍合同效力或任意调租权限。
- Singapore Courts：SCT 路径和准入条件，不是判定租客胜诉、专家费用不合理或所有争议必须调解的依据。
- CEA Dispute Resolution Scheme：消费者与房地产代理机构的 estate agency agreement 争议，不是所有房东与租客争议。切勿用其收费表充当租约鉴定费标准。

## 变更和评测如何报告

新标签与旧标签不一致可以是正确结果。另存差异表，记录案例、旧/新标签、具体新增依据和适用条件。比较依据变更与旧标签原有错误分开说明；不以模型预测决定标签。

旧的二十条已经曝光，重新标注后仍只是回归材料，不重新变成“未见过的外测”。若需要新泛化结果，另一个编写者应在全新窗口写一批新案例，再由第二个未见过作者意图/答案的窗口按本规则盲审。冻结预测器后再解封输入，不能先用它们调提示词。

新版正式成绩须绑定：案例哈希、标签哈希、依据版本、预测器代码、一次运行记录和全部非拒答结果的实质引用初审。旧版引用支持率不是新版分数；源码测试通过也不是引用实质支持率。模型自报“supported”只是产品门控，不能代替独立初审。

精确率、召回率、引用支持率越高越好；unsafe non-abstention 越低越好。不预先承诺任何成绩。若标签变更，旧/新成绩不能当作完全相同任务下的纯算法提升；须保留原标签评分或明确任务口径已变。
