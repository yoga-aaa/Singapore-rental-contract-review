## 根因及逐版改动

- v22 手写160字符内摘录、上下文列表和重复来源行带来机械拒绝；正面语义条件遗漏也存在。最后模型说 supported/adverse 不能直接计为检出。
- v23 编号合同/来源原文区间与当事人名称；模型选编号，程序还原确切原文。多区间还原包含中间限定条件的原文范围，不拼造句子。上下文单对象摘要绑定，不把确认当成理解证明。召回提高但主体仍可能选择整句。
- v24 把主体选项限制为当事人名称编号，却仍允许多个编号。实际响应重复选择同一角色的多个位置，程序按一般区间规则恢复中间文字，主体校验拒绝；因此成绩回退，完整保留失败结果。
- v25 主体改为一个名称编号或未知，不再允许重复位置；以中性角色问题区分付款/维修义务主体与通知者、收款人。来源直接选择完整登记段落编号，程序只恢复原文，不给未知主体、前提填入推断值。完整条件必须经语义比较和独立原文审核，不因引用全文自动支持。

保留同一情境、实际角色、房型、来源组、来源正面事实、因果、例外、锁定期、通知、补偿、宽限期和封顶等门槛。未知费用、一般客人规则和未识别机制不得靠其他背景资料猜测。修复了默认违约终止的词形边界反例；没有降低安全或内容支持要求。

仍采用两到四次有界调用：事实提取 → 原文比较 → 必要时一次集中重审 → 不接收此前结论/事实选择的独立原文审核。每例最多发布一个有限风险；旁支未批准。两次比较一致仍非外部专家证明。
