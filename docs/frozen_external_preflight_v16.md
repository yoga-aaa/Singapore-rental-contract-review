## 本步成果

- 将项目所有者在收到 v15 修订标签后回复的“ok下一步”记录为接受修订并继续的指示，不冒充逐条专家盲审证明。
- 原始案例、DeepSeek 原审核及 v15 建议均保留。生成另一个私有确认标签文件，而不是覆盖原审核。
- 单独保存纯案例输入与确认标签。预测入口只解析纯案例，标签文件只作字节完整性校验；不把标签、理由、裁决或整体清单送给被测模型。
- 保存运行源码、入口、依赖版本、测试、来源表、索引和固定原 PDF 的快照及精确字节 SHA-256。
- 运行前核对整个快照、当前源码文件集和逐文件哈希。源码、输入或配置变更会使该冻结不能继续使用；需另存新版本并重新确认，而不是悄悄更新锁。

所有源代码快照不包括 .env、API key、缓存或个人配置。模型 ID 及请求配置可锁定，但远端模型权重、供应商服务和底层实现不能由本地快照锁定。实际响应 ID、model、usage 等保存供核对。

## 预算与失败处理

拟定程序预算为最高 US$1、最多 40 次调用和 200,000 个总 token。预算未获本批次消费授权，不能直接运行。它是停止阈值，不是预计一定花 US$1，也不保证在此阈值内完成全部 20 条。

保持已有两阶段模型及提示词：

| 阶段 | 模型 | 输入 / 输出每百万 token 单价 | 最大输出 |
| --- | --- | --- | --- |
| 初审 | openai/gpt-4.1 | US$2 / US$8 | 1,600 token |
| 引用核验 | openai/gpt-4o | US$2.50 / US$10 | 1,300 token |

2026-10-03 核对的来源：[OpenRouter GPT-4.1](https://openrouter.ai/openai/gpt-4.1)、[OpenRouter GPT-4o](https://openrouter.ai/openai/gpt-4o)。实际以响应账单为准，不假设缓存折扣。

每次调用前，以 UTF-8 请求字节数加 1,024 的保守输入预留、最大输出和锁定单价计算预算。供应商限制为 OpenAI，禁止自动 fallback，要求支持请求参数，禁止使用允许收集数据的供应商，并通过 max_price 限制输入/输出及每请求价格；参考 [provider routing](https://openrouter.ai/docs/guides/routing/provider-selection)。

响应先记入日志，再处理模型 JSON；按响应的原生 token 和 usage.cost 记账。成本字段不会像旧工具那样在筛选整数时被丢弃。账单字段参考 [usage accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting)。

用量缺失、格式错误、网络异常、预留被超出或预算不足均立即停止，不自动重试，不覆盖或自动续跑。已经发生的调用和部分预测保留。程序预算不是账户级绝对硬限额；异常扣费可能高于单次预留，应如实报告，不能承诺接口异常时绝不会超额。

## 运行授权

预检查为默认行为，不读 key、不调用模型、不生成预测：

    python scripts/run_frozen_external.py --bundle <私有冻结目录>

实际运行还需要 --live 和 --authorization 指向新的用户授权记录。记录必须对应本冻结 manifest 的精确字节哈希，确认案例均为合成且无个人资料，明确同意发给 OpenRouter，并批准不低于程序阈值的美元预算。

之前对旧开发/外部批次的授权不自动覆盖本批次。本步不生成这个授权记录，不读取或显示 .env。

## 评分纪律

只保留既有的 precision、recall、citation validity 和 unsafe non-abstention；引用定位与实质支持分开，不能因引用存在就计作支持。报告准确分子/分母，无适用分母时标为 N/A。

预测、确认标签和人工引用审计分开：

1. 先用锁定的纯输入运行产品，不读取最终标签含义。
2. 完整 20 条全部完成后，才对照冻结标签计算 precision / recall / unsafe non-abstention。部分运行不伪装成全批次结果。
3. 为每个非弃答结果复核实际合同、完整引用/可见上下文、理由、逐项 comparison、具体影响和追问。先由项目助手记录 internal first pass，再交给用户核对；两者分别注明审计者与版本，不冒充独立法律专家盲审。三个审计判定为 supported、unsupported、uncertain；uncertain 按不支持计。
4. 一条结果的任一重要参考断言未被证据支持，整条结果不能计作 supported。模型 verifier 的 approve 不等同人工审计。
5. 在逐条内部引用审计完成前，实质支持率保持未评定；不能填零当失败，也不能填 100% 当通过。用户尚未核对时只可标为内部结果，不能描述成人工独立确认。

本批 20 条是分散条款，不是一份完整合同。可报告真实每条成本及批次总成本；不能把批次成本称为每份 agreement 成本。整份合同成本验证属于后续上传/切分工作。

本批已经在参考定位诊断中曝光，标签来自 AI 编写/分窗口 AI 审核、项目助手修订和项目所有者接受。它是外部来源诊断评测，不是严格未曝光、法律专家独立盲审的泛化证明。不得根据预测再修改锁定标签，或只重复挑选最好的一次成绩。
