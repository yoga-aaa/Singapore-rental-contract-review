# v15：参考 PDF 定位修复与离线验收

本步只修复参考资料提取、索引及引用定位，并准备私有标签复核材料。没有调用 OpenRouter，没有使用新案例调整提示词，没有生成新一轮 precision、recall 或引用实质支持率。

## 为什么需要修

CEA PDF 将编号放在左栏、正文放在右栏。旧的普通文本提取有时先列出多个编号，再列出正文，使正文被归到后一个编号。即使改成按页面位置提取，部分编号仍垂直居中在正文第二行，段落第一行可能误归上一条。

按 PDF 原页核对后，下面是可靠的定位区分。页数使用物理 PDF 页，而不是阅读器中的自定义页标签。

| 内容 | HDB | Private Residential |
| --- | --- | --- |
| 欠租、违约后的终止 | 8.1，PDF p.11 | 7.1，PDF p.12 |
| 自动终止事件 | 8.2，PDF p.11 | 7.2，PDF p.12 |
| 送达方式 / 视为送达 | 11.1 / 11.2，PDF p.12 | 12.1 / 12.2，PDF p.13 |
| 住户身份文件 / 变更通知 | 3.2 / 3.3，PDF p.6 | 3.2 / 3.3，PDF p.7 |
| 空调季度保养 / 故障因果责任 | 4.4 / 4.5，PDF p.7 | 4.4 / 4.5，PDF p.8 |
| 联合检查与后续损坏索赔 | 5.4，PDF p.10 | 5.5，PDF p.11 |
| 可选外交 / 解约安排 | Schedule ITEM 16，PDF p.4 | Schedule ITEM 14，PDF p.3 |

联合检查不是“退款后不得有任何索赔”：模板保留检查中确认的损坏/缺陷。违约补救期不是无例外的十四天：模板还允许双方约定其他期限。上述条件不可在解释中省略。

## 改动范围

1. 使用 pypdf 的 layout 模式读取页面，保留空行以辨认段落；失败时不退回已知有错位的普通提取。
2. 一个空行分隔段落内只有一个左栏编号时，将居中编号对齐到该段落开头。存在多个编号的密集块保持原顺序，不猜测。该规则适用于固定模板，不承诺覆盖任意合同排版。
3. 去除页眉页脚，遇到章节标题或附录时结束当前正文条款，避免跨章节串接。
4. 保留外交条款的 Applicable/Not Applicable、协商空白与证据条件。页底脚注保留在整页索引，不错误挂到最后一个 Schedule 项目。
5. 对空调、身份变更、联合检查等参考正文使用通用主题标记，避免正确提取的条款仍被主题筛选排除。没有新增针对私有案例编号的规则。
6. 让已有直接比较规则接受修正后的编号，并仍检查实际正文；历史错误编号仅为旧记录兼容，不作为正文正确性的保证。
7. 当前索引使用新文件名，构建时拒绝覆盖。当前单条 review、query 与通用评测入口改用新索引；历史重算脚本仍读取其原索引。

第一版候选仍漏了居中编号前的段落首句，离线核对发现后未当作最终版本使用；已保留该候选供追溯，并以段落对齐后的版本替换当前 v15。替换只涉及本步新生成的候选，不改旧索引。

## 验收结果

- 全部 128 项测试通过，包括 13 项新增排版/真实 PDF 回归测试及 6 项新版入口/引用路由测试。
- 新索引有 135 个条款/子条款/Schedule 片段，整页索引 45 页。它们不是 135 条独立评测案例。
- HDB 正文编号 56 个，Private 正文编号 57 个，与 layout 提取范围内的编号集合一致；没有缺失或多余编号。该检查不等同逐字语义完整性审计。
- 重新从固定来源生成两个索引，精确字节哈希均与当前版本一致；再次写同一输出会被拒绝，文件保持不变。
- 两份原 PDF、来源注册表、两个旧索引的精确字节哈希与修复前快照一致。
- 已曝光的 30 条开发案例在禁止读取 API key、禁止网络的诊断下：19 条走直接本地结果，6 条本地弃答，5 条仍需模型。这里只检验执行路径，不计算正确率；5 条没有预测结果。
- 本轮 API calls = 0，API tokens = 0。新外部案例没有运行产品预测。

## 复现

在仓库根目录运行：

    python -m unittest discover -s tests -q
    python scripts/check_v15_offline.py

第一次构建（输出尚不存在）：

    python scripts/build_source_index.py
    python scripts/build_section_index.py

需要生成另一个候选时，指定新的 --output 文件名；不要删除或覆盖锁定历史索引。索引文件由源 PDF 确定性生成，本地衍生目录不作为待提交源码。

## 本步不证明什么

工程测试通过不代表模型判断正确，也不代表引用实质支持达到 95%。历史分数保留其原文件、原来源和原分母；旧索引存在定位问题，旧分数不能当成修正后定位有效性的证明。

私有新案例来自 AI 编写、分窗口 AI 审核和项目所有者检查，缺少确切模型版本/聊天记录及独立法律专家盲审。项目助手现已查看这些案例并据此诊断提取问题。可以进行透明披露的外部来源诊断评测，但不能称为严格未曝光、专家独立标注的泛化评测。

标签修订必须在产品预测前由用户确认并锁定，不能看模型输出再迁就标签。最终 API 评测需另行锁定代码、索引、输入和预算，获得该批发送及消费授权，并单独复核引用实质支持。本步到此停止。
