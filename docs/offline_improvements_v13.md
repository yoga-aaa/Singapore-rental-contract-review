# v13：引用与判断逻辑的本地改进

本轮按照用户要求完成代码修改和离线检查，**OpenRouter 调用为 0，API tokens 为 0**。91 项测试通过，包含模拟模型响应的完整两次调用流程。v13 尚未产生新的真实模型评测结果，不能据此宣称达到 95% 的引用实质支持率。

## 已实现的改进

| 原问题 | v13 的处理 |
|---|---|
| 一看到押金就停止主题识别，漏掉终止租约等事项 | 按句收集多个主题；区分押金金额、扣款清单与独立的租金/维修/水电义务。押金或维修程序中的通知不会自动被当成终止租约通知。 |
| 引用转租子项时缺少“租客不得……”的前提 | 优先取包含完整禁止前提的父条款，去掉已被父条款包含的重复片段。不同住房类型继续分别检索。 |
| 引用短片段截掉条件或例外 | 程序为引用附加同一注册条款的原文上下文，并严格核验其内容。上下文在请求中按条款去重。 |
| 自由解释与合同实际文字脱节 | 模型必须提供每项比较的合同原句、参考证据序号、参考主张、关系和租客影响。合同原句必须是输入的精确子串，证据序号和主题必须匹配。 |
| 复核模型只给笼统“同意”，仍可能批准错误理由 | 要求逐项作出支持/不支持/不确定判断及说明，并复核原句、责任人、触发条件、期限和例外。缺项、错序或无支持的判断不能释放。 |
| 有些错误解释可以修正，却直接被弃权 | 第一阶段检查结构、原句和证据；第二次模型调用可基于同一证据修正解释、关系、参考主张和租客影响；最终再运行严格检查。无法修正则弃权。 |
| 没写通知程序被推断为取消通知保护 | 扩大遗漏表达的识别范围，包括“without requiring/specifying”“does not require”等；否定必须针对同一项保护。“without delay”或另一个事项的免责不会变成通知豁免。 |
| 有条件许可被等同于禁止；暂扣被等同于扣除 | 增加条件转租、紧急维修例外、迟报导致费用、争议款暂扣与扣款程序之间的矛盾检查。 |
| 参考资料没写，被说成“只允许”“没有这种规则” | 拦截摘录无法支持的排他性、穷尽性和整体不存在主张；提示模型陈述引用实际写明的正面规则。 |
| 快速规则只匹配关键词，忽略责任人或否定 | 核对维修超额费用实际由谁承担、证件实际由谁提供；限制带额外条件或否定的快速通过。快速规则的结果也要经过共同引用和解释校验。 |

比较关系分为语义相当、对租客更有利、可能对租客不利、无法确定。更有利的许可本身可以不触发复核，但不能说成与禁止条款“完全相符”。`no_material_difference_found` 需要覆盖识别出的所有实际义务；`review_required` 需要至少一项有原句和引用支持的潜在不利事项。

## 本地自测结果与检查中发现的问题

从 53 项增加到 **91 项测试**，新增检查覆盖遗漏表达变体、无关的“without”、通知与补救期分别判断、责任人反转、费用承担反转、条件转租、维修例外、原句捏造、错误证据编号、伪造上下文、逐项复核缺失、错误批准、解释修正和两次调用的用量归集。

检查中发现并修正了三项问题：旧证件规则把居住者的责任当成租客的责任；最初收紧的维修规则没有识别“费用由房东承担”的被动表达；主题识别需要把紧邻押金条款的通知句放回押金语境。相应测试包含正确例子和改变责任人、费用承担方、否定或条件后的反例，避免仅因缺少参考资料而“测试通过”。

[`v13_offline_diagnostics.json`](v13_offline_diagnostics.json) 保存了本地诊断快照：

- 30 条开发案例：19 条由本地规则输出，6 条在本地弃权，**5 条需要真实模型检验，尚未运行**。`model_needed` 是运行状态，不是 `insufficient_evidence` 的预测标签。
- 保存的 v12 外部非弃权解释共 13 条：9 条被新检查拒绝，4 条通过本地检查。9 条包括原审计的全部 7 条不支持、1 条不确定，以及此前判为支持的 `EXT_17`。后者因“参考没有这种裁量权”的表述被更严格地拒绝，需要在付费检验中检查是否修正为支持得住的解释，而非只增加弃权。
- 已曝光的 20 条案例在四个检索名额内，均找到了覆盖所识别主题的参考片段。**这只是主题覆盖检查，不能证明检索证据完整或判断正确。**
- 历史 v12 预测、标签、原引用审计和参考索引未修改，原评分仍可复算为 5/13。新规则拒绝旧解释并不把它改记为一个新的正确预测。

诊断脚本在运行期间阻断 API 密钥读取和所有模型网络入口。单条命令也支持 `--offline`，到达模型阶段会明确返回 `model_needed`。付费开发评测保存新的 `comparisons_json`，并在剩余调用额度不足两次时停止，不会拿一次额度启动一个最多两次调用的评审。

## 复现本轮检查

以下命令不调用 OpenRouter：

```powershell
python -m unittest discover -s tests -q
python scripts/check_v13_offline.py
python scripts/review_clause_live.py HDB "The Tenant may sublet with prior written consent." --offline
python scripts/score_external_evaluation.py
```

诊断脚本可使用 `--output` 指向一个新 JSON 文件保存快照；它拒绝覆盖已有文件。最后一条命令只复算历史 v12 分数。

## 进入真实模型检验前的状态

本地能够检查的结构、原文定位、已知矛盾和执行路径已通过测试。**真实模型能否稳定遵守新结构、完整理解条件和给出受支持的解释，仍需实际检验**。这些语义问题不能靠 91 个测试证明已经消失。正则检查也可能误判新的表达方式，故仍须检查召回、弃权和解释质量。

下一轮应先在开发案例上做有明确预算的新运行，分别检查 precision、recall、unsafe non-abstention 和逐条引用实质支持情况，同时记录弃权及拒绝原因。为支持逐项分析，草稿和复核输出上限分别从 850/450 调整为 1,600/1,300 tokens；实际用量尚未测量，不能沿用旧成本估计。每条仍最多两次模型调用。

这 20 条外部案例的预测和错误现已曝光，并被用于本轮回归改进；以后在它们上的重跑必须称为**回归测试**。完成开发检验并冻结版本后，应使用新编写、独立复核标签的外部案例估计泛化表现。不得用增加弃权制造 95% 的引用分数：必须同时披露分母、弃权情况和风险召回。
