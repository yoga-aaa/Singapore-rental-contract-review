## 根因与改动

v19 的九条漏检已经收到主要比较资料，未发生资料截断。增加参考或降低门控不能解决把因果、形式条件、时限、双方退出权和例外混为一谈的问题。v21 已把抽取与判断分开，但仍先截断候选、后去重，而且判断失败就结束；逐字绑定也不等于语义支持。

| 问题 | v22 处理 | 保留的限制 |
| --- | --- | --- |
| 重复任务占满容量 | 全量发现 → 按机制、原文分段和来源组去重 → 最多选 12 个任务，明确记录被排除项 | 有真实任务被排除不能输出有限 pass；不静默批准未知部分 |
| 时间、累计责任、例外位于邻句 | 绑定至多三个相邻原文分段，处理依赖片段、指代和长句切分 | 不跨空白段落或不相关主题推断指代；完整合同仍给模型，分段确认不证明语义 |
| Lessor、Lessee、pays back 等表述漏配 | 有限别名只用于检索／校验匹配副本 | 资料、引用、合同摘录均保留原文；不同措辞不自动成为风险 |
| 检索和新任务拆分不一致 | 同一发现规则先保留必需来源组的完整登记段落，再补候选 | 保持房型、官方资料用途边界；不截短证据省 tokens，不以一般付款／住户／调解资料替代具体规则 |
| 有依据但抽取或判断失误便弃答 | 可恢复问题最多进行一次单任务原文重审，不接收旧意见 | 缺资料、非法结构、错房型和不支持机制不靠猜测修复；规则拒绝不直接赋风险标签 |

## 调用与发布路径

1. 抽取逐字条件事实，不输出意见或标签。
2. 独立比较原合同和完整来源，同义条件可以等价；未决任务保留未知。
3. 有候选时，第三次做原文独立审核，一致才发布。
4. 无候选但有直接依据和可恢复错误时，第三次集中重审；若产生候选，第四次独立审核，否则弃答。每例最多一次重审，不循环刷结果。

一般比较用 GPT-4o、随后审核用 GPT-4.1；重审用 GPT-4.1、随后审核用 GPT-4o，避免模型审核它刚给的关系判断。提取与审核仍可能用同一模型，全部模型同一服务商，因此不能包装为专家独立验证。固定机制提示仍可能引入共同偏差；最终严格整条回复引用支持审计不能省略。

最多发布一个通过两次原文比较的有限风险，未知邻居仍未批准。有限 pass 需要所有选择任务有正面同机制证据、两次一致，且任务和必需资料没有截断。引用、解释、后果、追问及上下文要整条一起审计，不只检查链接存在。

为控制成本，只删不相关机制 rubric 示例、缩小允许输出类型；安全边界与完整证据不删。单任务重审／审核最多输出 1600 tokens，其余最多 2400。
